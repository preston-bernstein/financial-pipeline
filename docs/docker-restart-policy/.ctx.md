## CONTEXT.md
# financial-pipeline — domain model
This is financial-pipeline's domain reference: the entities, vocabulary, and tools that other docs and code assume you already know.
Key entities: Transaction (Plaid-sourced), Snapshot (browser-scraped investment balances via Betterment/Vanguard/Fidelity), Run (one adapter execution record: source, started_at, completed_at, status running|success|failure, rows_written, error_message — used by get_adapter_health for staleness), Materialization (triggered via pg_notify), MonthlySpending, JournalEntry.
Taps (plaid-tap, structured API) vs Adapters (betterment/vanguard/fidelity, Playwright browser scrape, require seeded session).
Observability: this repo is DELIBERATELY EXCLUDED from the shared home-lab Loki instance (ADR 0018) — it handles live Plaid/brokerage data and pino's key-name redact deny-list isn't trusted alone to keep that data out of a shared multi-repo-queryable log store. Logs stay local (`docker logs <container>` on the deploy host). Compensating coverage: a payload-free `GET /metrics` endpoint on mcp-server, computed directly from Postgres (survives container restart) — run outcomes, staleness timestamps, etc.
Deploy: Docker Compose, images built and pushed via `make deploy` (build → ssh docker load → ssh docker compose up -d) against a host set via NAS_HOST/NAS_USER env vars (now pointed at the desktop per the 2026-07-17 migration).
